# 演示视频分镜脚本 — 校园智能气象服务系统

> 赛事要求：MP4，单文件 ≤ 200MB，**时长 ≤ 5 分钟**；需全面展示功能与操作流程，**重点突出智能体的运行过程**（接收请求 → 分析决策 → 反馈结果）、智能体与其他模块的协同，以及场景中的实际应用价值。本作品为软件应用赛道，无需实物原型画面。
>
> 本脚本成片目标 **4 分 32 秒**，留 28 秒安全余量。

---

## 一、叙事主线

不按「功能清单」平铺，而是用一个具体事件把两类智能体串起来：

**一场 12 m/s 的校园大风：数据智能体把它变成预警，决策智能体把它变成值班人员能执行的一句话。**

全片围绕两条智能体链展开，并刻意让二者**交替出镜**，让评委看到「协同」而不是两个孤立模块：

| 智能体 | 驱动方式 | 在片中的角色 | 出现镜次 |
|---|---|---|---|
| 数据智能体（采集/质控/预报/告警/报表） | 规则、阈值与统计算法 | 把原始报文变成可信数据与预警 | 镜 3、镜 4、镜 7 |
| 决策智能体（助手） | 大模型 + 工具调用 + 知识库 | 把数据与规范变成人能执行的结论 | 镜 5、镜 6 |
| 告警 AI 文案 | 大模型（与规则并列存储） | 规则给事实、模型给处置动作 | 镜 4 |

> **口径提醒（务必统一）**：数据智能体**不含大模型**，是规则与算法驱动的流水线；系统中的大模型能力集中在决策智能体与告警文案。片中不要笼统说「五个智能体都是 AI」，评委追问时会失分。正确说法是「五个数据智能体 + 一个决策智能体」。

## 二、拍摄前置准备（按此清单逐项确认）

| 项 | 要求 | 确认方式 |
|---|---|---|
| 服务状态 | 前端 5173、后端 8080、MySQL/InfluxDB/Redis/RabbitMQ/MQTT 全部在跑 | 见下方检查命令 |
| **模拟器** | 已开启，**每 15 秒自动产生一条观测** | 无需手工造数；看日志是否每 15 秒出现「质控完成」 |
| **日志过滤** | 后端日志是 **DEBUG 级**，MyBatis 的 SQL 会把画面刷满，必须过滤后再拍 | 见下方过滤命令 |
| 演示数据 | 无需手工灌数：后端启动时自动回填 7 天逐小时历史 | 若已清空时序库，重启后端即会回填，趋势图直接有数据 |
| 浏览器 | 缩放 100%、隐藏书签栏、单一窗口、深色主题一致 | 全片统一，避免画面风格跳变 |
| 干扰项 | 关闭微信/邮件/系统通知；关闭自动更新弹窗 | 录屏前逐一确认 |
| 录屏 | 1920×1080 / 30fps 以上；麦克风单独试录 10 秒回听 | 旁白与画面分开录，后期再对轨 |
| **不可拍项** | **RabbitMQ 管理台不可用**（15672 未监听），不要安排「看消息队列」的画面 | 协同证据改用日志窗口 + 界面结果呈现 |

### 服务检查命令

```
Get-NetTCPConnection -LocalPort 5173,8080,6379,8086,1883,5672 -State Listen
```

### 日志窗口命令（镜 3、镜 5 用，直接复制执行后保持窗口不动）

```
Get-Content tools\app.log -Wait -Tail 6 | Select-String '质控完成|告警|助手问答完成'
```

这条命令会把噪音滤掉，只留下三类关键行，画面干净且每 15 秒自动刷新：

- `质控完成: station=FARM02, qc=passed, msgId=0-1790405750742` —— 数据智能体流水线在跑
- `助手问答完成: model=deepseek-chat, toolCount=3, tools=[listStations,queryRealtime,queryRealtime], costMs=3015` —— 决策智能体的决策轨迹
- 告警相关行 —— 告警智能体在判定

> 本机实测（2026-09-26）现存活告警 3 条：大风蓝色 ×2、暴雨橙色（由黄色升级）。开场镜头可直接用这些真实数据。

## 五、录制与后期要点

1. **旁白单独录**，不要一边操作一边说。操作会打断语速，且鼠标声会进麦。
2. **操作放慢**。鼠标移动用「慢—停—再动」，每次点击后停 0.5 秒再动，给后期留剪辑点。
3. **分屏是重点工程**。镜 3、5B、5D 都要分屏。建议：先把左右两段画面分别全屏录好，后期在剪辑轨上并排对齐时间轴，比现场调窗口可靠得多。
4. **日志文字要能被看清**。终端字号调大到 16~18pt，窗口宽度只留够一行（`Select-String` 过滤后的行较长，可用 `-Wrap` 或拉宽窗口）。
5. **时间轴对齐技巧**：镜 5B 的关键是「日志出现 tools=[…] 的那一刻」与「页面从等待态切换为回答」在时间上吻合。后期对齐到同一帧，说服力最强。
6. **不要用加速处理关键证据**。镜 5B 的日志行、镜 5C 的工具清单展开，都是「证明 AI 真在做事」的证据，加速会让人怀疑是剪辑出来的。
7. **成片导出**：H.264 / MP4，1080p，码率 8~12 Mbps（5 分钟约 300~450MB，**超过 200MB 上限** → 请压到 **4~6 Mbps**，或导出后交平台二次压缩，务必核对最终文件大小）。
8. **合规**：若镜头中出现登录页，先确认页面上没有明文演示账号提示；出现真实姓名/手机号的位置一律打码或避开。
9. **备份**：原始录屏工程与无字幕成片各留一份，评委复核或需要重剪时不至于返工。

## 六、必须避免的四个坑

| 坑 | 后果 | 规避 |
|---|---|---|
| 把五个数据智能体说成「都是大模型驱动的」 | 被追问即失分 | 统一口径：数据智能体（规则算法）+ 决策智能体（大模型） |
| 拍 RabbitMQ 管理台看队列 | 该页面不可用，现场卡住 | 协同证据改用日志窗口 + 界面结果 |
| 直接拍未过滤的后端日志 | MyBatis DEBUG SQL 刷屏，观众看不清 | 用第二节给出的 `Select-String` 过滤命令 |
| 正片超过 5 分钟或文件超过 200MB | 直接被判不合规 | 剪辑完成后**同时核对时长与文件大小**两项 |

## 附：智能体运行过程的一句话总结（用于答辩口述）

> 数据智能体是这条链路上的「手」——按规则与算法把原始报文变成可信数据和预警；决策智能体是「脑」和「嘴」——用大模型规划该查什么、查完再用中文讲给值班人员听。手不依赖脑，所以大模型服务挂了，校园的预警不会停。
